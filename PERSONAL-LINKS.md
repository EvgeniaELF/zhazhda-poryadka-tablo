# Персональные ссылки и отправка из GitHub · вариант 1.2.0

30 октября 2026. **Подготовлено для решения пользователя, ещё не установлено.** Личные ссылки и кнопка копирования на опубликованном табло уже работают. Предыдущая отправка Яндекс→Telegram не подтверждалась; этот вариант отправляет сообщение непосредственно из GitHub Actions. Новых облачных архивов и адаптера для него не требуется.

## Ссылка и карточки

Формат после установки: `https://evgeniaelf.github.io/zhazhda-poryadka-tablo/#card=p04&round=17`. Это карточки Жени · болид №9 за 17-й круг. Постоянный cardId не зависит от имени; его нужно сохранять при переименовании и перестановке строк. Новым участникам назначается новый уникальный cardId, старые не переиспользуются для другого человека.

Ссылка открывает сразу «Личный трек» и «Личный рубеж» с прежними кнопками скачивания. Открытие карточек по букве имени меняет адрес; кнопка под «Личным рубежом» копирует ссылку. При запрете clipboard появляется выделенное поле для ручного копирования. Поддержаны Escape, возврат фокуса, Tab внутри окна, Back/Forward. Неизвестный участник или круг не заменяется первым из списка.

Круг закреплён, данные остаются живыми: это не неизменяемый архив старого PNG. Скачанный PNG сохраняет конкретный результат. После следующей публикации при необходимости обновить страницу. Автоопроса открытой вкладки нет.

## Сборка и история

В исходном BOARD_DATA изменились только новые поля cardId у 17 профилей. Сезоны, круги, отметки, firstReport, joinedRound, паузы и даты сохранены. Контрольный тест сравнивает исторические данные с прежним основанием; при намеренной правке истории его отпечаток обновляется только после отдельной сверки.

Каждая сборка по-прежнему читает все таблицы Buildin и заново объединяет исходную историю с текущими событиями. В _site выходят только index.html, 14 прежних ресурсов, personal-links.js и cards.json. В cards.json — публичные cardId/имена, круг/тип отметки, хэш ID события и номер публикации. Внутренние Buildin page/database ID и секреты не публикуются. В HTML появляется совпадающий маркер выпуска. personal-links.js копируется только как обычный файл, не симлинк.

## Согласуемое изменение доступа

В окружении **github-pages** существующего репозитория нужны два **Environment secrets**:

| Имя | Что хранится |
| --- | --- |
| NAVIGATOR_TELEGRAM_BOT_TOKEN | Действующий токен navigator_admin_bot, тот же, что уже используется в Яндексе и адаптере |
| NAVIGATOR_ADMIN_TELEGRAM_ID | Числовой Telegram ID владельца пульта, тот же ADMIN_TELEGRAM_ID |

Путь: Settings → Environments → github-pages → Environment secrets → Add secret. Это именно Secrets, не Variables, не файл кода и не сообщение в чат. Полные значения вводит пользователь у себя. Токен в Яндексе сохраняется. Новых прав fine-grained PAT не требуется.

Environment secrets ограничены jobs, использующими это окружение. В подготовленном workflow оба значения переданы через env только последнему шагу уведомления; в build-job и сборку сайта они не передаются. Код с правом выполнения в этом окружении получает возможность использовать токен бота — это реальное расширение доверия к GitHub, требующее решения пользователя. Секреты не публикуются в HTML, cards.json, артефактах и логах; GitHub дополнительно маскирует сохранённые secrets.

## Как работает доставка

1. Функция после подтверждённой отметки запрашивает прежний workflow main/publish=true и передаёт хэш события notice_event.
2. GitHub публикует сайт и только затем запускает notify-publication.cjs.
3. Скрипт проверяет свой repository/owner ID, workflow/main/тип запуска и ожидаемые runId/attempt/SHA. Читает только закреплённые публичные cards.json и HTML, проверяет совпадение обоих с этим выпуском и единственную точную отметку/участника.
4. Через Telegram getMe проверяет, что токен относится к navigator_admin_bot.
5. Делает один sendMessage на ID из секрета NAVIGATOR_ADMIN_TELEGRAM_ID. Отправку подтверждает только положительный ответ Telegram с ID сообщения и совпадающим private chat.

Запроса GitHub→Яндекс для уведомления нет. Приём команд ботом продолжает работать в прежнем режиме; сам шаг уведомления после публикации не требует работающего компьютера/адаптера. Участнице сообщение автоматически не отправляется, владелец пересылает ссылку самостоятельно.

Ссылка фиксирует участника и круг, а при открытии показывает текущие опубликованные данные. Сообщение сохраняется в переписке, в нём только URL-кнопка. Новое нажатие меню его не заменяет.

## Пределы и ошибки

Read-only проверки распространения Pages повторяются до шести раз с паузой5с. Редиректы запрещены, HTTPS/TLS проверяется стандартным клиентом. Объёмы и время запросов ограничены. Адрес сайта, Telegram host и API-методы закреплены в коде; свободный chat_id/URL из входа или опубликованных данных не принимается.

После неоднозначной попытки sendMessage слепого автоматического повтора нет. Явный новый запуск или новый клик существующей отметки может прислать сообщение повторно. Постоянного журнала «ровно один раз» нет. Любой внешний канал может быть недоступен; реальная отправка из GitHub пока не проверена. Ошибка уведомления не отменяет опубликованный сайт и не повторяет запись Buildin. Последний шаг и Summary показывают безопасный код причины. Ссылку всегда можно скопировать на сайте.

Расписание без notice_event и обычной ручной публикации без notice_event не присылают сообщения. Queue:max, cron7 6,18 * * * UTC (09:07/21:07МСК), Node24, Ubuntu24.04, SHA-pins и правила объединения сохраняются.

## Файлы для установки после решения

```text
.github/workflows/buildin-board.yml
scripts/notify-publication.cjs
tests/personal-links.test.cjs
tests/telegram-publication.test.cjs
PERSONAL-LINKS.md
BUILDIN-SYNC.md
```

Нужно обновить весь sender вместе с workflow, а не только добавить переменные к старому sender. index.html, personal-links.js, BOARD_DATA, assets и Buildin не редактируются. .github при проблеме загрузки заменить целым YAML через Edit. Сохранить в main после решения пользователя, затем добавить два Environment secrets. Пока установка не завершена, можно держать TABLO_CARDS_ENABLED=false; затем true. TABLO_SYNC_ENABLED=true и BUILDIN_SYNC_ENABLED=true сохраняются. Если пользователь уже успела выключить TABLO_CARDS_ENABLED после обсуждения отказа от уведомлений, вернуть true только после установки и секретов.

Прежние функция2.3.5-r2 и адаптер1.0.11 остаются. Новый код не обращается к publication_notice в Яндексе. Сам старый защищённый callback в функции не удалён, но новый workflow его не вызывает.

Проверка после установки: повторить действующую существующую отметку, дождаться нового deploy, отдельного сообщения со ссылкой, проверить человека/круг и оба скачивания. Искусственные новые отметки для теста не нужны. Не запускать старые runs повторно — они используют прежний sender. Отключение запросов уведомлений — TABLO_CARDS_ENABLED=false; ссылки/копирование остаются.
