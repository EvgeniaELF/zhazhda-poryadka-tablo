# Buildin → существующее табло · 1.0.0

Подготовлено 29 октября 2026. Репозиторий: https://github.com/evgeniaelf/zhazhda-poryadka-tablo . Адрес сайта сохраняется: https://evgeniaelf.github.io/zhazhda-poryadka-tablo/ .

## Что готово

GitHub Actions читает две базы Buildin и собирает HTML существующего табло. Рабочие Telegram-функция 2.3.1, адаптер 1.0.7, их переменные и ключи не меняются. GitHub не становится приёмником сообщений Telegram. Для работы бота в нынешнем режиме всё ещё нужны включённые ПК/Ubuntu/VPN; сборка уже записанных данных на GitHub от ПК не зависит.

Основа `index.html` — последняя сохранённая версия 250 от 29.10.2026, 02:58 МСК (круг 17). При подготовке публичный репозиторий был на коммите `19a291dcc82987f29e235b30f9f88fa5e846d887`, круг 16. Архив содержит обновлённый исходный HTML и новые файлы автоматизации; оформление и все картинки берутся из существующего репозитория. Это комплект для установки, а не автономная копия всех картинок сайта.

### Правила первой версии

- Из Buildin добавляются **Старт** и **Финиш**, включая отметки за прошлые круги. Дубли по одному человеку/кругу/типу не увеличивают счётчики.
- Основная идентификация события — ID страницы из «Карточка участника». У старых событий без связи допускается только точное однозначное совпадение полного имени. Разные Ани/Жени/Лены не объединяются.
- Все 17 профилей, существующие сезоны, визитки, даты первого отчёта/выезда на трек, история пауз, поездки и осознанные пропуски сохраняются из исходного HTML. «Дата старта» Buildin не заменяет `firstReport` автоматически.
- Старые отметки, уже встроенные в HTML, остаются: таблица Buildin пока не содержит полный исторический архив. Это **пополнение проверенной истории**, а не полное зеркалирование двух таблиц.
- Поэтому удаление/исправление события, уже встроенного в исходный HTML, не убирает эту историческую отметку автоматически. Её надо исправить и в исходном блоке `BOARD_DATA`. Новое событие, отсутствующее в исходном HTML и удалённое из Buildin, исчезнет при следующей сборке.
- Состав участников и статусы сверяются со всеми профилями, включая пит-стоп. При новом/переименованном/удалённом участнике или несовпадении статуса сборка останавливается: сначала согласуем профиль и точные даты паузы/возвращения в исходном табло. Время обнаружения статуса не принимается за историческую дату.
- Новая неделя по Москве открывает следующий круг внутри уже настроенного сезона 2 до круга 24. После этого требуется подготовить следующий сезон. Будущие события, чужая/неоднозначная связь и конфликт с особой исторической отметкой блокируют публикацию.
- Buildin только читается: GET схем и POST запросов списка. Созданий/изменений/удалений страниц нет.
- При ошибке чтения или проверки опубликованный сайт не заменяется. GitHub хранит последний успешный деплой. Чтение двух таблиц не является атомарным снимком сервиса.

## Установка по шагам

### 1. Загрузить файлы в существующий репозиторий

Не загружай ZIP как один файл. Распакуй его: в корне будут `index.html`, `buildin-sync.json`, `BUILDIN-SYNC.md`, `.gitignore`, папки `scripts`, `tests`, скрытая папка `.github/workflows`.

Через GitHub можно создать новую ветку `buildin-sync-preparation`, затем **Add file → Upload files** и загрузить файлы с сохранением путей. Папка `.github` может быть скрыта Проводником; если она не загрузилась, создай её файл через **Add file → Create new file**, введя полный путь `.github/workflows/buildin-board.yml`, и вставь содержимое из архива. Проверь в списке файлов наличие этого пути. Содержимое ZIP не содержит секретов.

Картинки и старые страницы из репозитория не удалять. Перед слиянием проверь, не появилась ли более свежая версия `index.html` в другой ветке работы. Установочный HTML не следует накладывать поверх более свежих правок без сверки. У workflow нет запуска на `push`, поэтому сам коммит автоматизацию не включает; однако если Pages сейчас публикуется из ветки main, замена `index.html` в main может обновить статическое табло сразу.

### 2. Добавить один закрытый секрет

В репозитории: **Settings → Secrets and variables → Actions → Secrets → New repository secret**.

- Name: `BUILDIN_API_TOKEN`
- Secret: действующий ключ интеграции Buildin, у которой есть доступ к обеим базам.

Вводи значение только в это закрытое поле GitHub. Не вставляй ключ в HTML, JSON, сообщения чата, README или комментарии коммитов. Telegram-токен, webhook-секрет, SETUP_KEY и отдельный GitHub PAT этой автоматизации не нужны. GitHub хранит ключ для запуска процесса; права существующего Buildin-ключа могут быть шире чтения, хотя этот код выполняет только чтение.

ID двух баз уже записаны в `buildin-sync.json`. Это идентификаторы, а не пароли. Названия свойств: «Участник», «Статус» в участниках; «Участник», «Круг», «Событие», «Карточка участника» в событиях.

### 3. Первый ручной запуск без публикации

После переноса workflow в основную ветку: **Actions → Buildin → табло → Run workflow**. Выбери **main**, оставь **publish выключенным**. Для надёжной видимости workflow сначала должен быть в основной ветке. Не создавай пока переменную BUILDIN_SYNC_ENABLED.

Успешный запуск покажет число участников, событий, уникальных отметок и повторов. Внизу запуска появится `tablo-preview`: скачай и распакуй. В `sync-report.json` виден список новых отметок относительно исходного HTML, а в `_site/index.html` — предварительный сайт с картинками в той же папке. Данные в этом отчёте относятся к живому чтению GitHub только после фактического запуска.

Сверяем круг, людей, даты дней на треке, сохранённый сезон 1 и новую контрольную отметку. Если отчёт сообщает несовпадение состава/статусов или другую ошибку — ничего не публикуем, исправляем конкретную причину. Отчёт не печатает ключи, сырые API-ответы и внутренние ID страниц. В публичном репозитории логи и артефакты могут быть доступны другим: в них только те имена/отметки, которые предназначены для публичного табло.

### 4. Первая публикация

После успешного предварительного просмотра: **Settings → Pages → Build and deployment → Source → GitHub Actions**. Затем тот же ручной запуск на **main**, включи **publish**. Сайт останется по прежнему адресу. Настройка источника Pages и публикация здесь ещё не выполнены.

Данные не коммитятся каждые 15 минут: GitHub собирает готовую страницу и публикует её как Pages artifact. Поэтому `index.html` в репозитории остаётся исходной проверенной историей и шаблоном, а опубликованный HTML дополнен последними событиями. Старые HTML-файлы из репозитория в публикуемый каталог не копируются.

### 5. Включить расписание

Только после принятой ручной публикации: **Settings → Secrets and variables → Actions → Variables → New repository variable**.

- Name: `BUILDIN_SYNC_ENABLED`
- Value: `true`

Workflow запрашивает обновление на 7-й, 22-й, 37-й и 52-й минуте каждого часа (интервал 15 минут). Время запуска и публикации может задерживаться у GitHub; это не мгновенное обновление после кнопки бота. При 60 днях отсутствия активности в публичном репозитории GitHub может отключить расписание — его потребуется включить вновь. Автоматическая запись событий в Buildin по-прежнему зависит от рабочего пути Telegram/адаптера.

Чтобы остановить расписание: поменяй переменную на `false` или отключи workflow. Последняя публикация сохранится. Для возврата к прежнему способу публикации восстанови нужный коммит исходного HTML и источник Pages; запись истории в Buildin и работа бота от этого не меняются.

## Проверка разработчиком

`node --test tests/*.test.cjs` (Node.js 22 или новее).

Локальные проверки используют подставные API-ответы. Они не означают успешного живого доступа GitHub к Buildin, правильности введённого секрета или фактической публикации. Прогон проверяет сохранение истории и дат, несколько одноимённых людей, повторы, связь по ID, ошибки/пагинацию, смену круга, экранирование HTML и полный сборочный путь без утечки секретов.

Публичная папка `_site` содержит только `index.html` и 14 разрешённых изображений/SVG. Код синхронизации, настройки, ответы API и секреты в неё не попадают. Ключ Buildin доступен только шагу чтения. Редиректы запрещены, HTTPS/TLS проверяется стандартным Node fetch. Права workflow на содержимое репозитория — только чтение; публикация отдельным заданием с `pages:write` и `id-token:write`. Внешние Actions закреплены SHA. Автозапуски выключены, пока переменная явно не станет true.
