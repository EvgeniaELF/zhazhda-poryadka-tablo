## Результат

После проверки именно опубликованного выпуска GitHub отправляет владельцу два отдельных сообщения по порядку. Первое готово для пересылки участнику:

✅ Карточки обновлены.

Старт 17 круга · принят 🏎️
карточки Личный трек и Личный рубеж можно посмотреть и скачать тут: Болид №7

В настоящем сообщении название участника является HTML-ссылкой на персональные карточки. Для финиша используется Финиш N круга. Технический длинный URL и кнопка под карточками не выводятся. Имена и href экранируются; просмотр ссылки отключён.

Следом отдельным сообщением приходит «Выбери следующее действие.» с кнопками «Ещё отметка в этом круге» (r:N) и «← В меню» (home). Они совместимы с текущей бизнес-логикой пульта. Меню можно редактировать, карточки остаются выше в истории.

## Установка

Распаковать navigator-telegram-message-v1.2.2.zip. В существующем репозитории EvgeniaELF/zhazhda-poryadka-tablo открыть Code → Add file → Upload files в корне. Загрузить папки scripts, tests и PERSONAL-LINKS.md из архива, сохранив пути. В списке должны быть ровно три файла:

- scripts/notify-publication.cjs
- tests/telegram-publication.test.cjs
- PERSONAL-LINKS.md

Сохранить одним коммитом в main. Тесты обновляются вместе со скриптом, иначе прежняя проверка ожидает старую кнопку под карточками. Полный старый каталог проекта загружать не нужно.

Уже существующие Environment secrets окружения github-pages остаются NAVIGATOR_TELEGRAM_BOT_TOKEN и NAVIGATOR_ADMIN_TELEGRAM_ID. BUILDIN_API_TOKEN и BUILDIN_SYNC_ENABLED=true сохраняются. Права окружения main, SHA-пины workflow и cron7 6,18 * * * UTC остаются как были. id-token:write по-прежнему нужен публикации Pages.

После коммита на VPS выполнить navigatorctl check. Проверка читает публичный sender и требует маркер TELEGRAM_MENU_DELIVERED. Затем переход к takeover отдельным шагом: не запускать двух приёмников Telegram одновременно. Установка sender не переключает webhook и не создаёт событий Buildin. Реальную доставку проверять новым действием после запуска VPS; повтор старого run использует старый код.

## Проверки и ограничения

Проверки выпуска/run/attempt/SHA, события и участника, собственной идентичности бота и фиксированного личного адресата сохранены. Секреты используются только в trusted deploy-step; запросы к Pages и публичным исходникам их не получают. После подтверждения карточек записывается TELEGRAM_DELIVERED, после подтверждения меню — TELEGRAM_MENU_DELIVERED.

Оба сообщения отправляются по одной попытке. При ошибке или неопределённом результате меню код TELEGRAM_MENU_UNCONFIRMED и Summary честно сообщают: карточки отправлены, меню не подтверждено, открыть /start. Автоматического повтора карточек/меню нет. Новый явный запуск может создать повторное сообщение; exactly-once не гарантируется. Сбой уведомления не отменяет опубликованное табло и не повторяет запись Buildin.

Тесты используют подставные API, рабочих ключей и настоящих сообщений нет. Предыдущая рабочая отправка1.2.0 проверена пользователем; живая отправка1.2.2 после установки ещё требуется.

Постоянные cardId, ссылки #card=p04&round=17, кнопки скачивания и копирования на сайте не меняются. Данные по ссылке остаются живыми, круг закреплён. Публичные карточки не являются приватным доступом. Вкладку табло по-прежнему обновляют вручную.
