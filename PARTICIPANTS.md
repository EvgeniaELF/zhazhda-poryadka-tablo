# Участницы, пит-стопы и сезоны

Подготовлено 12 ноября 2026 года для архива коммита `26e8a6211d20b891f84d0aa028840da82dc24996`. Это готовый к проверке пакет, пока не подключённый к рабочему Buildin и не опубликованный в GitHub. Проверки API выполнены на моделируемых ответах; настоящую схему и перенос проверяем предпросмотром ниже.

## Как устроено управление

- **«Участники» в Buildin** — создание участницы, дата и круг присоединения, пит-стоп и возвращение.
- **«Табло» в Buildin** — события «Старт» и «Финиш», поступающие через действующий пульт.
- **GitHub Actions** — проверка, сохранение принятой истории и публикация.
- **Служебная ветка `tablo-participants-state`** — автоматический журнал принятых профилей, всех пауз и событий. Вручную её редактировать не требуется.

Сборщик только читает Buildin. Действующий бот на Selectel и его настройки этот пакет не изменяет. Отдельное задание GitHub получает право записи в содержимое этого репозитория для сохранения истории. Buildin-токен и Telegram-секреты этому заданию не передаются.

## Поля базы «Участники»

Существующие названия, типы, формулы и связи сохраняем. Добавляем пять свойств с точными названиями:

| Свойство | Тип | Как заполняется |
|---|---|---|
| **Дата старта** | Дата, уже существует | Первый день для счётчика дней на треке |
| **Круг присоединения** | Число, новое | Первый круг личной истории |
| **Дата начала пит-стопа** | Дата, новое | Первый день, который исключается из дней на треке |
| **Пит-стоп с круга** | Число, новое | Круг первого значка 🔧 |
| **Дата возвращения** | Дата, новое | Первый день, который снова входит в дни на треке; пусто, пока пауза продолжается |
| **Готово к табло** | Чекбокс, новое | Включить после проверки всей карточки; перед административным изменением снять |

В датах указываем один день без времени и диапазона. Круги — целые числа. Статусы сохраняем прежними: «На треке» / «На пит-стопе».

Добавление этих свойств само по себе не включает новый режим. У прежних участниц галочки «Готово к табло» на первом этапе оставляем снятыми: их проверенные даты, круги и паузы берутся из сохранённой истории. Их не выводим из даты создания события в Buildin.

## Смысл дат

Женя вводит первый день пит-стопа. Программа сама переводит его в прежний формат: `pausedAt` — предыдущий день, последний засчитанный. `resumedAt` совпадает с введённой датой возвращения.

Пример Ани: начало паузы **5 ноября** → `pausedAt: 2026-11-04`; значок 🔧 — **19-й круг**. Уже принятый старт 18-го сохраняется. Дата паузы и круг значка имеют разные задачи.

Если возвращение 20 ноября, дни 5–19 ноября исключаются, а 20 ноября засчитывается. Воскресенья входят в дни на треке, если не относятся к паузе.

## Первый перенос

1. Добавить пять новых полей в «Участники». Оставить «Готово к табло» снятым у прежних участниц. Новых участниц и новых пауз пока не добавлять.
2. Установить **все файлы пакета одним коммитом в отдельной ветке**, например `participants-management`. Папки `scripts`, `tests`, `.github` должны сохранить расположение. ZIP в репозиторий не загружают: загружают его распакованные файлы из `update/`. Существующие изображения сохраняются.
3. Сверить исходную версию с указанным выше коммитом. Если основной код после присланного архива уже менялся, пакет нужно сначала совместить с этими изменениями. В архиве есть `update.patch` для просмотра точного различия; он применяется из корня репозитория через `git apply --check update.patch`, затем `git apply update.patch`.
4. В Actions → **Buildin → табло** выбрать эту ветку. Запустить с **publish = false**, **manage_preview = true**, пустыми **bootstrap_digest** и **notice_event**. Тесты и сборка проверят настоящие типы свойств и прочитают обе базы. Записи Buildin, история GitHub и действующий сайт этим запуском не изменяются.
5. Скачать артефакт **tablo-preview**. Сверить 17 участниц, даты и старые ссылки `p01`–`p17` в `sync-report.json` → `participantsPreview`. Можно передать этот отчёт в нашу ветку: он содержит только сведения для публичного табло. Сырые ответы API и токены в нём отсутствуют.
6. Проверить PR и объединить в `main`. Переменную **BUILDIN_PARTICIPANT_MANAGEMENT** пока не включать.
7. Запустить предпросмотр из `main` с теми же параметрами. После сверки скопировать из отчёта **код первого сопоставления** — 64 символа. Это контрольная сумма, не пароль.
8. Запустить из `main`: **publish = true**, **manage_preview = true**, **bootstrap_digest = проверенный код**, **notice_event пусто**. Сначала создастся ветка истории с полным снимком, затем опубликуется сайт. Без правильного кода первый перенос не публикуется.
9. После успешной публикации создать repository variable **BUILDIN_PARTICIPANT_MANAGEMENT = true**. Обычные запуски бота и расписания будут использовать новую модель. Между первым переносом и включением переменной прежний режим блокирует публикацию, чтобы сохранить историю.
10. Проверить открытие старой личной ссылки и обычный старт/финиш через пульт. Новую участницу сначала проверить предпросмотром; затем подтвердить настоящую публикацию и её личную ссылку. Эти живые проверки ещё не выполнены.

При блокировке записи служебной ветки политикой GitHub задание завершится ошибкой до публикации. Личный токен с дополнительными правами для этого не создаём: сначала проверяем политику обычного `GITHUB_TOKEN` в репозитории.

## Новая участница

1. Создать карточку в «Участники» с различимой публичной подписью. Для тёзок добавить номер болида.
2. Указать «Дата старта», «Круг присоединения», статус «На треке». Поля пит-стопа и возвращения оставить пустыми.
3. Проверить данные и включить «Готово к табло».
4. Запустить GitHub Actions с **publish = true**; служебные поля запуска оставить пустыми, manage_preview можно оставить выключенным — постоянная переменная уже включает режим.
5. Проверить отчёт и опубликованную карточку. Постоянную ссылку программа создаёт сама по идентичности записи Buildin.

До подтверждения новую карточку сборщик считает черновиком. Пульт пока использует прежний фильтр статуса, поэтому отметки через него ставим после подготовки и публикации участницы.

## Пит-стоп

1. Снять «Готово к табло».
2. Для прежней карточки, которую ещё не редактировали в новом режиме, заполнить исходные дату старта и круг присоединения по справке ниже. Принятые значения сохраняем.
3. Указать «Дата начала пит-стопа» и «Пит-стоп с круга», очистить «Дата возвращения», выбрать статус «На пит-стопе».
4. Проверить карточку, включить «Готово к табло» и запустить публикацию из GitHub.

Подтверждённые старты и финиши сохраняются. Новая отметка в круге продолжающейся паузы требует предварительной сверки возвращения.

## Возвращение и следующая пауза

1. Снять «Готово к табло».
2. Сохранить дату начала и круг текущей паузы; заполнить «Дата возвращения» и выбрать «На треке».
3. Включить «Готово к табло», запустить публикацию и дождаться успеха. **Возвращение нужно сохранить отдельным обновлением до следующей паузы.**
4. Для следующего пит-стопа снять галочку, заменить начало и круг на новые, очистить возвращение и выбрать «На пит-стопе». Затем подтвердить и опубликовать.

Предыдущий эпизод уже останется в служебной истории. Один и тот же запуск не создаёт повторную паузу. При возврате в том же круге счётчик дней возобновляется сразу; уже принятые отметки имеют приоритет над значком пит-стопа.

## Защита истории и восстановление

- Пока «Готово к табло» снято, административные изменения прежнего профиля не применяются. Новые события бота при этом продолжают обрабатываться.
- Неполная пара даты и круга или противоречие статуса паузе останавливают новую публикацию. Предыдущий сайт остаётся доступен.
- Принятые дату старта, круг присоединения, закрытые паузы и старые события нельзя исправить обычным перезаписыванием: нужна отдельная сверка. Переименование подписи сохраняет личную ссылку и историю.
- Исчезновение ранее принятой участницы, события или повреждение снимка также останавливает публикацию. Запись участницы не удаляют ради пит-стопа и не пересоздают ради переименования.
- Снимок сохраняется **до Pages**. Если снимок сохранился, а Pages завершился ошибкой, повторяем обычный запуск с теми же данными. Принятые изменения не дублируются.
- После первого переноса не удаляем ветку `tablo-participants-state` и не отключаем режим ради отката. Для остановки публикаций отключаем сам workflow, сохраняя последнюю страницу и историю; затем исправляем код, совместимый со снимком.
- Ветка истории содержит только публичные сведения табло и хеши идентификаторов. Она также видна в публичном репозитории. Она не заменяет полный закрытый бэкап Buildin или секретов сервера.

## Сезоны

Сквозная нумерация продолжается: 1–12 — сезон 1, 13–24 — сезон 2, 25–36 — сезон 3. Далее программа открывает по 12 кругов в сезоне. Московский понедельник открывает новый круг; подпись периода остаётся понедельник–суббота. Дни и личные достижения накапливаются, итоги сезона ограничены его кругами.
