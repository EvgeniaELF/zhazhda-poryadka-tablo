# Персональные ссылки на карточки · 1.1.0

Подготовлено 30 октября 2026. Эти файлы добавляют открытие двух существующих карточек участника по одной ссылке и уведомление владельца бота после успешной публикации. Установка в рабочий репозиторий и функцию выполняется отдельно; наличие исходников не означает, что новая версия уже опубликована.

## Ссылка и карточки

Формат после установки: `https://evgeniaelf.github.io/zhazhda-poryadka-tablo/#card=p04&round=17`. Это карточки Жени · болид №9 за 17-й круг. Постоянный cardId не зависит от имени; его нужно сохранять при переименовании и перестановке строк. Новым участникам назначается новый уникальный cardId, старые не переиспользуются для другого человека.

Ссылка открывает сразу «Личный трек» и «Личный рубеж» с прежними кнопками скачивания. Открытие карточек по букве имени меняет адрес; кнопка под «Личным рубежом» копирует ссылку. При запрете clipboard появляется выделенное поле для ручного копирования. Поддержаны Escape, возврат фокуса, Tab внутри окна, Back/Forward. Неизвестный участник или круг не заменяется первым из списка.

Круг закреплён, данные остаются живыми: это не неизменяемый архив старого PNG. Скачанный PNG сохраняет конкретный результат. После следующей публикации при необходимости обновить страницу. Автоопроса открытой вкладки нет.

## Сборка и история

В исходном BOARD_DATA изменились только новые поля cardId у 17 профилей. Сезоны, круги, отметки, firstReport, joinedRound, паузы и даты сохранены. Контрольный тест сравнивает исторические данные с прежним основанием; при намеренной правке истории его отпечаток обновляется только после отдельной сверки.

Каждая сборка по-прежнему читает все таблицы Buildin и заново объединяет исходную историю с текущими событиями. В _site выходят только index.html, 14 прежних ресурсов, personal-links.js и cards.json. В cards.json — публичные cardId/имена, круг/тип отметки, хэш ID события и номер публикации. Внутренние Buildin page/database ID и секреты не публикуются. В HTML появляется совпадающий маркер выпуска. personal-links.js копируется только как обычный файл, не симлинк.

## Сообщение после публикации

Облачная функция 2.3.5 при TABLO_CARDS_ENABLED=true добавляет в workflow_dispatch только notice_event — хэш ID подтверждённого события. Поле вручную оставлять пустым. Старый формат publish=true остаётся при выключенном флаге; ручной запуск и расписание без notice_event не отправляют личных уведомлений.

После успешного deploy шаг notify-publication.cjs получает временный OIDC JWT GitHub и обращается к закреплённой функции. Функция проверяет подпись, issuer/audience, постоянные ID владельца и репозитория, workflow main, окружение github-pages, время и runId/attempt/SHA. Затем проверяет, что именно эта версия HTML/cards.json опубликована и содержит запрошенную отметку. Только тогда отправляет владельцу сообщение со ссылкой. Участнице оно автоматически не отправляется; владелец пересылает ссылку самостоятельно.

Telegram-токен и webhook-секрет не добавляются в GitHub. Постоянного callback-ключа нет. В deploy-job уже требуется id-token:write для Pages; contents:read нужен для кода уведомления. Новых repository secrets не требуется.

Сбой уведомления не отменяет публикацию и не создаёт вторую отметку. До отправки Telegram допускается ограниченное ожидание распространения Pages. Неоднозначная отправка не повторяется автоматически. При проблеме последний шаг и Summary показывают предупреждение; ссылку можно скопировать на сайте. Кэш 256/20 минут не является постоянным журналом, после аварии или явного нового запуска возможен повтор сообщения.

Очередь workflow queue:max сохраняет до 100 ожидающих запусков; cancel-in-progress=false. Расписание остаётся 09:07/21:07 МСК, Node24, Ubuntu24.04 и закреплённые SHA Actions сохранены.

## Проверка и порядок включения

1. Установить эти файлы в main и выполнить Run workflow с publish=true и пустым notice_event.
2. Проверить открытие/копирование личной ссылки и скачивание обоих PNG.
3. Установить функцию 2.3.5 и совместимый адаптер 1.0.11, сохранив все пять действующих Lockbox-привязок.
4. Включить обычную переменную функции TABLO_CARDS_ENABLED=true. TABLO_SYNC_ENABLED=true и GitHub BUILDIN_SYNC_ENABLED=true сохраняются.
5. Повторить действующую существующую отметку. Новой строки не должно появиться; после публикации ожидается сообщение с персональной ссылкой.

Отключение уведомлений — TABLO_CARDS_ENABLED=false. Перед откатом workflow выключить этот флаг. Исторические данные и таблицы для отката не удалять.

Проверки: `node --test tests/*.test.cjs` — 38 тестов на Node22 и Node24. Облачный и транспортный наборы проверяются в соответствующих пакетах. Сквозной локальный сценарий не заменяет живую проверку GitHub OIDC и исходящей сети Яндекс → Telegram после установки.

## Исправление транспорта r1 — 30 октября 2026

Yandex Cloud Functions использует Authorization для платформенной авторизации и удаляет его до вызова функции. GitHub OIDC JWT передаётся в X-Navigator-Publication-Authorization: Bearer <JWT>. Исправлены обе стороны: scripts/notify-publication.cjs и index.js функции. Проверки подписи, репозитория, workflow, получателя и публикации сохранены. Версия протокола функции 2.3.5 и адаптер 1.0.11 совместимы без обновления адаптера. Workflow YAML не меняется.

На живых запусках 18/19 до исправления сайт успешно опубликован, а отправка уведомления завершилась предупреждением. Отказ Authorization на уровне Яндекса подтверждён безопасным запросом с заведомо недействующим тестовым значением; без него запрос доходит до обработчика. После установки r1 нужен повторный живой тест существующей отметки.
